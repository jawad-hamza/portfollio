# Fiverr case-study PDFs

One self-contained PDF per major project. Generated by `../build_project_pdfs.py`
from the same `assets/data.js` that drives the website, so nothing drifts.

**Page 1 is the cover, and Fiverr renders page 1 as the gallery thumbnail** —
so each cover carries the project name, status, the one-line pitch and the
strongest screenshot on a dark ground.

Every file is 3–5 pages and well under Fiverr's 15 MB per-PDF limit
(largest here is ~1 MB).

## Structure of each PDF

| Page | Content |
| --- | --- |
| 1 | Dark cover — name, status stamp, deployment code, one-line pitch, hero screenshot, contact |
| 2 | What the system does, the spec table, the full stack, module map where there is one |
| 3–4 | Screens, captured from the running application |
| Last | "Work with me" — services tailored to that project's field, how I work, contact |

## Uploading to Fiverr

Fiverr's gig gallery takes **2 PDFs per gig**. Pair them so the second one
supports the first, for example:

- *Retail POS gig* → `Vendora` + `Restaurant-Management-System`
- *Healthcare gig* → `Blood-Bank-Management-System` + `DHQ-Hospital-Management-System`
- *AI gig* → `Embeddable-RAG-Chatbot-Platform` + `Store-Listen`
- *Web / brand gig* → `FutureSpace` + `Apex-Unify`

## Regenerating

```bash
# 1. export the project data from data.js
node -e "const fs=require('fs');const s=fs.readFileSync('assets/data.js','utf8');
fs.writeFileSync('assets/data.json',JSON.stringify(new Function(s+';return{PROJECTS,STATUS,DOMAINS,REGISTERS};')(),null,1))"

# 2. build every PDF
python build_project_pdfs.py
```

Edit which projects get a PDF by changing the `GIGS` list at the bottom of
`build_project_pdfs.py`. Edit the services copy in the `SERVICES` dict.
